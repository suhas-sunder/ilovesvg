# Run 3 conversion quality corpus

Tested the Node 20 builds of the narrow reliability release at f67c008 and the checkerboard candidate at 39e607f. The server entry digests differ and only the candidate bundle contains the new checker detector. The home client asset is identical, as expected for a server preprocessing change.

The corpus covers logos, thin line art, flat illustration, complex color regions, fine text, transparency, genuine checkerboards, ordinary neutral bands, the historical UI fixture and a landscape photograph. Chromium uploaded each fixture through the home converter and downloaded the selected preset's SVG. The report includes source-relative alpha overlap, white-backed RGB error, dark and edge recall, path and group counts, viewBox, SHA-256, file size and elapsed browser workflow time. Group count is a markup count, not a substitute for the editor layer contract. The photograph is Hannes Röst's [Fronalpstock panorama](https://commons.wikimedia.org/wiki/File:Fronalpstock_big.jpg) under [CC BY-SA 3.0](https://creativecommons.org/licenses/by-sa/3.0/). The harness resized and cropped it to 320×240, then encoded a local PNG without source metadata. Neither the photo nor generated outputs are committed. The input used was the Commons 960px JPEG with SHA-256 bf3b5d46079793930b7fb8715d552e242f898d00b95ff3544189aaab8afef9e6.

All 44 conversions and downloads completed on the representative matrix. In a second run, all eight lettering exports completed and the new visual regression gate rejected the candidate. It allows up to five percentage points of newly dark pixels in light areas so antialiased edge movement alone does not fail the fixture. The source and before/after renders show a large filled band, consistent with the measured failure. The detector preserves the input matte, and Accurate Lineart's existing threshold turns the newly retained light gray into foreground. The same detector protects real opaque color areas in layered presets. Changing the lineart threshold or scope to bypass this one regression would require its own coverage and legibility study.

The median end-to-end browser workflow was about 2.07 seconds on the baseline and 2.05 seconds on the candidate. Windows server lifetime peak working sets observed during local testing were about 197 and 212 MiB respectively. These were warm, shared local test processes. They include other work and do not establish per-conversion peak memory, a performance improvement, or a production resource budget.

Flat High and Photo High match byte for byte on the UI fixture and the photograph. They differ on the flat illustration and the complex regions on both builds. Source review confirms a shared compact VTracer core with family-specific overlay parameters and a per-color fallback when the compact result has fewer than 12 editable groups. Equal output can therefore be input dependent. The existing eight tier progression checks require an improvement in a scalar detail score for successive tiers. That expectation is not a per-image guarantee. The photograph shows a real increase in paths from 56 to 133 and a modest RGB improvement from 8.91 to 8.50 from Flat High to Amazing, while the smallest lettering remains unreadable in layered output. Keep the score failures as diagnostic evidence and prioritize legibility. The precision failure concerns the 39 KB default output, so this run did not round geometry to satisfy the precision target.

PR #6 remains experimental. This branch adds the corpus and its gate without replacing the tracing engine. To reproduce, run local Node 20 builds of PR #4 and PR #6 on ports 3012 and 3013 or supply CHECKER_BROWSER_BASELINE_URL and CHECKER_BROWSER_CANDIDATE_URL. Set PLAYWRIGHT_MODULE and RASTER_CHROMIUM_EXECUTABLE if using a local Playwright installation. Supply QUALITY_CORPUS_PHOTO for a photograph and QUALITY_CORPUS_OUT for a fresh report directory. Set QUALITY_CORPUS_FIXTURES=lettering for the focused rejection check. The report, SVGs and screenshots stay in the ignored output directory. A failing exit from the focused run is expected against this checkerboard candidate.
