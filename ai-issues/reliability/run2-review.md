## Header and memory review boundaries

PNG/JPEG/WebP signature probes reject unreadable dimensions before the recognized raster worker path. JPEG segment offsets, lengths and EXIF IFD accesses are bounded; source files are never modified by header inspection. Root's new JPEG scan preserves large legal metadata by skipping payload bytes rather than loading the full file. A malformed padding test found 126739 Blob.slice calls while reading only 257572 bytes from a 131329-byte source. Root added a separate 2048-read and 512-total-fill-byte ceiling; metadata, late EXIF and budget regressions pass with that correction.

The normalizer's 192/384 MiB budgets estimate decoded source, target/canvas/encoding storage and compressed payload copies. They do not prove an iOS peak allocation bound and do not include every possible GPU, decoder, existing WASM or concurrent tracing allocation. The original fast path and server/client ceilings have not been expanded. No memory-ceiling increase is recommended on the available evidence. Physical iPhone RAM and OS tab termination remain unverified.

Synthetic two-frame red/blue animated WebP and APNG sources were tested in Chromium, Firefox and WebKit using both ImageBitmap and forced HTMLImageElement normalization. The 9000x120 sources produce static 8000x106 PNGs with the red first frame in all six decoder/engine combinations. This does not establish animation preservation, a many-frame memory bound, or physical iOS decoding behavior. SVG tracing produces static output.

A separate 9000x120 WebP fixture contains EXIF orientation 6. Sharp independently applies the tag and returns a 120x9000 portrait; the tested browser decoders ignore the tag and report raw 9000x120. Before the guard, oversized browser normalization emitted landscape 8000x106 and discarded the metadata. This was a risk in the new recovery path; acceptance of this oversized input on main was not established. The corrected candidate declines resizing a WebP flagged with EXIF and explains how to export a correctly oriented PNG or JPEG. The format probe passes all three engines: the refusal occurs before any decode or preparation callback, and an ordinary EXIF WebP returns the exact original File. JPEG orientation is handled separately. No expensive raw decoder or new image dependency was introduced.

Existing centerline handling still limits compressed bytes but can decode a full source before reducing its trace canvas. That is a pre-existing resource risk and is not represented as fixed by the new post-read cancellation check. Any additional source-pixel admission change should be separately measured and preserve existing successful workflows.

All new test data are deterministic synthetic images. No private original file, source pixels, EXIF/location, filenames from user uploads or credentials were sent to production, GitHub, analytics or logs. The supplied original incident directory was absent when this review began.

## Additional shared-consumer publication defect and focused correction

The original scalar setClientData calls could be batched when one shared promise settled several consumers. An executable each-render observation showed a three-consumer group publishing only producer A and final consumer C, never B. Actual Chromium UI confirmed **two succeeded cards rather than three**. Another actual browser case submitted shared A/B server work, then replaced it with a different-source C: C completed, but the superseded group showed **failed/running** instead of both settled. These are real user-visible status failures, not just mock expectations.

A minimal FIFO now holds per-consumer settled outcomes and publishes one per render/effect while retaining the existing scalar fetcher.data API and route handlers. It does not change tracing, source bytes or global job cancellation. Queued cancellation is filtered before publication; unmount clears retained SVG references. Existing owned request/preset/run IDs travel with each outcome. The FIFO becomes empty after normal settlement, and tests hold mock renders to verify canceled/unmounted queued SVGs are never presented and their references are released.

There was also a transient ownership issue when the producer consumer was canceled before fallback began while a live shared consumer remained. The server still uses the producer's request identity; its raw response could briefly revive the canceled producer card before the live consumer's mapped result. An each-render assertion reproduced that leak. A targeted canceled-run filter now suppresses the producer's raw presentation while still allowing the pending promise to settle the live consumer. Raw successful responses for uncanceled consumers remain supported, avoiding a broader history/API rewrite.
