# SVG sprite generator acceptance

Package F is **validated locally and ready for owner review with the Phase 3 correction**. PR #21's original application head, **40856446cf75a0a58070b72bf218002789bad48d**, reproduced a malformed-path output defect. The corrected tests ran against the Node 20 production-mode integrated source tree **7bc288cb5b4076101de77d8c1c042be901020417** in Chromium 147.0.7727.15 and Playwright WebKit 26.4. The release sequence must carry the correction at package F and revalidate the exact future GitHub candidate. Owner approval, production deployment, physical-device coverage and real ad-network verification remain separate gates.

## Confirmed defect and correction

The parser treated a decimal point as valid without a following digit, then copied the raw path data into the symbol. Both engines truncated malformed path data and rendered the preceding geometry. The baseline route accepted and downloaded a blue compound ring with `d="M1 1 H23 V23 H1Z M6 6 H18 V18. H6Z"`. In fresh HTML with the actual snippet, RGB at both the outer band and the expected hole was `[31,81,255]`. The valid version with `V18` rendered the center white `[255,255,255]`. The malformed `H6..1` variant left an antialiased partial center at `[153,176,255]`.

`app/client/lib/converter/svgSprite.ts` now applies the strict fractional-digit syntax to path numbers only, matching both browser engines and the SVG 2 path grammar. Correction commit `10c8f8db05b2061c6be314d8516a946725610911` includes the focused browser regressions. ViewBox, coordinates and transform attributes retain their existing number handling. Focused route regressions reject trailing decimals before another command, at the end, before an exponent and at adjacent double decimals. Numeric neighbors include compact adjacency with a signed exponent, a leading fractional dot, a complete trailing fractional component, and exponent notation. The accepted ring renders a white center and blue outer band. [SVG 2 path grammar](https://www.w3.org/TR/SVG/paths.html#PathDataBNF).

## Security, output and resource runs

- **Actual route and downloaded file.** The [product run](sprite-product.mjs) exercised 23 file-specific rejection cases in each engine, including malformed and Unicode path syntax, XML declarations and entities, CSS-escaped or encoded URLs, nested foreign namespaces, cross-file and duplicate references, an overlong gradient chain, overflow, masks and dash tricks. The chain boundary passed at 12 elements and failed at 13. Error focus moved to the visible inline error and the old download was absent.
- **Downloaded pixels.** Each engine produced the same 1,291-byte four-symbol sprite for the synthetic collision batch, SHA-256 `c0969b60f37598164412c0bd3726000246564607e9501161a9cf07f2a3e68e0a`. Filenames mapped deterministically to `icon-token`, `icon-token-2`, `icon-token-2-2` and `icon-svg`. XML structure, internal references and ID uniqueness passed. In fresh HTML, actual download bytes plus the exact UI snippets rendered an inherited linear gradient, a distinct radial gradient, a compound hole and a stretched nonsquare solid icon. The source-derived gradient oracles differed by at most 0.0253/255 per channel on Chromium and 0.000073/255 on WebKit. Repeated use differed by at most 0.02192/255, within the renderer's pixel rounding. Decorative and informative versions of the solid ring had identical pixels. Out-of-bounds art was clipped at the nonsquare viewBox. Escaped HTML-looking title text stayed text, and no uploaded-source requests or same-origin writes were observed.
- **Ownership and accessibility.** The actual route previewed four files, allowed keyboard activation and explicit clipboard-denial fallback, selected the correct markup or snippet, reset decorative mode on clear and kept download bytes stable after reselection. The existing ownership suite passed both engines on the corrected source for replacement, clear, held reads after route exit, stale copy feedback, simulated browser drop, focus and exact blob-URL revocation. The updated package F browser suite passed 63 cases in each engine, including the four new path regressions. Sprite layout passed at 320, 375, 390, 430, 768, 1024, 1440 and 1920 CSS px in both engines. Scoped axe checks passed on the editor's initial and ready states at 320 and 1440 px and on the error state at 320 px. A separate 2560 px Chromium whole-page probe still reports shared navigation label-content findings. Reviewed mobile preview screenshots show four intact previews, visible focus, selected snippets and fallback feedback. See the [Chromium](screenshots/F-chromium.jpg) and [WebKit](screenshots/F-webkit.jpg) contact sheets.
- **Resource watchdog.** The [resource run](sprite-resources.mjs) used a separate 12-second process watchdog for each of 13 Chromium and 13 WebKit cases. It checked exact and over-limit UTF-8 file and batch sizes, node/geometry boundaries, 15,006 self-intersecting segments distributed across three previews, 5,701 arc commands in one preview, a nearly degenerate reflected radial gradient over 990 shapes, huge accumulated translations and malformed dashes. The observed maxima were 51 ms for validation and 171 ms for rasterization in this run. The preliminary concurrent probe was slower (1,164 ms for one dense Chromium preview) and also completed. Historical numeric-dash input remains rejected. These runs cover the selected worst cases and measured local browser behavior. Native SVG precision can still affect extreme legal geometry, including a microscopic transformed viewport that rasterized differently in a supplemental probe.
- **Installed PostHog.** The [privacy run](sprite-posthog.mjs) used the actual app initialization and installed PostHog 1.320.0 lazy recorder. A local browser interceptor supplied the synthetic feature configuration and installed script and decoded intercepted `/e/` and `/s/` bodies, including gzipped event fields. Chromium emitted 3 analytics events and 35 replay events and WebKit emitted 3 and 32. Two outside control clicks and two outside full snapshots were present in both engines while private success and error states were present. Synthetic filename, title, source markup and error markers and blob URLs were absent. No service received the traffic.

The same-document inline workflow tested here is the documented one. Existing WebKit tests report an external `<use>` gradient rendering limitation. This run preserves the documented inline support and adds no runtime package, storage, analytics, routing or publication change.

## Reproduce

Set `BASE_URL` to a local production-mode build of the corrected candidate, and `PLAYWRIGHT_MODULE` to an installed Playwright module if it cannot be resolved normally. Run from the repository root on Node 20.

```powershell
node ai-issues/phase3/sprite-product.mjs
node ai-issues/phase3/sprite-posthog.mjs
node ai-issues/phase3/sprite-resources.mjs
node ai-issues/releases/weekly/phase2-sprite/svg-sprite-browser.mjs
node ai-issues/releases/weekly/phase2-sprite/svg-sprite-ownership.mjs chromium
node ai-issues/releases/weekly/phase2-sprite/svg-sprite-ownership.mjs webkit
```
