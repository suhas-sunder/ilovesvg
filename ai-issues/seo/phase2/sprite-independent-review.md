# Independent SVG sprite security and architecture review

Review date: 2026-11-13. Foundation: PR #12 at `78dda78994ea90e7b3a839725021bc316463434e`. The implementation author and this reviewer were separate agents. Review scope includes `app/client/lib/converter/svgSprite.ts`, `app/routes/svg-sprite-generator.tsx`, the phase 2 sprite browser suite, and the installed PostHog 1.320.0 autocapture and replay behavior.

## Findings and fixes

- **Browser stall in the original dashed-stroke validator.** The repeated separator expression could backtrack exponentially on a 32-item malformed dash list with two spaces between items. A worker watchdog cut off the original expression after 600 ms in Chromium and WebKit. The interim linear validator removed that stall.
- **Browser stall while drawing accepted dashed strokes.** An icon with 995 short lines and a dash period of 0.00005 user units fit all input budgets, then exceeded an 8-second independent process watchdog in Chromium and WebKit. The candidate now rejects numeric dash arrays and dash offsets before making a preview or export, while allowing solid strokes and explicit `stroke-dasharray="none"`. The unsupported-format copy offers filled outlines as the workaround. Original malformed and valid-but-costly cases are covered by the durable browser suite.
- **Composed transform overflow.** Repeated nested scale transforms were accepted and yielded blank output. The candidate checks bounded finite affine transforms and near-singularity for operations, accumulated transform lists, and nested geometry. The nested-scale reproduction and over-bound transform list now fail before preview. The bounds also apply to local gradient transform lists.
- **Path command fidelity.** JavaScript case folding maps the Unicode long s to ASCII `S`. Both browsers discarded the rest of a path containing the Unicode letter after the move command. The candidate requires an ASCII path command before normalizing its case.
- **ViewBox clipping.** Both engines clip artwork at the symbol viewport. A nonsquare standalone SVG can otherwise paint into the letterbox when geometry extends beyond the viewBox. The tool documents the clip. The core comparisons use artwork that fits its own viewBox.

## Independent evidence

- The browser suite at `ai-issues/releases/weekly/phase2-sprite/svg-sprite-browser.mjs` transpiles the repository parser and runs it in Chromium and WebKit. Same-document inline `<use>` rendered the gradient and solid pixels. Three image-mode preview comparisons per engine had a worst mean channel difference under 0.536 out of 255. This covers the inline workflow advertised by the tool.
- An additional local browser probe rejected 18 hostile or invalid inputs on both engines. Cases included prefix and namespace alias tricks, XML stylesheet PI inside a title, character-reference injection in paint, CSS escape/remote URI candidates, duplicate href variants, cross-file fragment references, event attributes, malformed path flags and delimiters. Escaped fake image/script markup in title and description remained text when the generated SVG was parsed as HTML. It initiated no unintended HTTP request and did not execute.
- The reworked parser rejected the 995-path dashed-stroke reproduction, the near-budget smaller dash variants, and the nested transform overflow. Dense gradients (490 stops used by 505 shapes), nearly degenerate reflected gradients, extreme repeated radial paint, dense fill winding and solid paths near the geometry budget completed under the local 8-second watchdog. The slowest measured raster among those accepted examples was about 292 ms for a single 96 px preview in desktop Playwright WebKit. Extreme geometry can still be intentionally offscreen, degenerate, or outside native browser rendering precision.
- The input parser uses a detached XML document with DTD, PI, CDATA and unsupported namespaces blocked. The preview and download use rebuilt, serialized allowlisted DOM. Local references target generated same-symbol gradient IDs and their chains are bounded. Source text is not assigned to innerHTML by the route. There is no sprite loader, action, upload request, persistence or new analytics integration.
- The installed PostHog autocapture code walks ancestor classes and suppresses the `ph-no-capture` subtree. The installed rrweb v2 bundle excluded dynamic filename-like markers, private attributes and text from a blocked subtree in both browsers while capturing an outside positive control. The route places chooser, error, preview and output controls in the blocked subtree.

## Integrated browser review

- **Stale read after route exit.** In the first registered production snapshot, WebKit could settle a held read after the chooser detached but before passive effect cleanup. The old selection then issued one extra read. A layout-effect cleanup invalidates the operation at unmount. The regression harness now settles the held read from a mutation observer when the chooser detaches and verifies the second file never gets read. Clear, replacement, stale clipboard feedback, drop, and blob URL cleanup across clear, replacement, error and navigation also passed both engines.
- **Symbol field association.** The old wrapped label had the expected accessibility-tree name in both engines. Playwright's exact label query could include its nested option text. The separate label and control ID make the association explicit and passed the full workflow.
- **Privacy and output.** Both browsers tested the actual route with request interception and with the installed PostHog 1.320.0 replay recorder emitting into a local in-memory buffer. The recorder captured the outside positive control and excluded private marker content from the populated editor and error state. The generated download matched the markup text and rendered gradient and solid pixels when placed into HTML with the tool's snippet.
- **Layout and accessibility.** All seven widths from 320 through 1440 px passed in Chromium and WebKit, plus Chromium at 2560 px. Scoped axe reported zero WCAG A/AA violations for the tested editor states. The shared ad wrappers triggered the existing whole-page ARIA rule. Requests to external services were intercepted.

See the [reproducible validation and screenshots](../../releases/weekly/phase2-sprite/validation.md). These checks used a local production-mode build and automated engines. No physical-device, real ad-network, deployed analytics or production verification was performed.
