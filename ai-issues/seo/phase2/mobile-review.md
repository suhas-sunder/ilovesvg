# Mobile image recovery

The existing `/how-it-works/troubleshooting` route gains a server-rendered recovery section at `#mobile-image-recovery`. It walks through a supported export, smaller pixel dimensions, orientation and transparency, and recovery after a failed or interrupted conversion. It builds on `ai-issues/seo/drafts/mobile-input-recovery.md` from `origin/codex/reliability-hardening-2026-11-08`. The package uses PR #12's application foundation at `78dda78994ea90e7b3a839725021bc316463434e`.

## Claims and evidence

- `/png-to-svg-converter` uses `prepareRasterUpload.ts` to read actual PNG, JPEG, and WebP signatures and estimate normalization cost. Its PNG normalization preserves source alpha. The memory policy can reject a highly compressed image with too many pixels. The 6,000 × 4,000 to 3,000 × 2,000 example is an aspect-ratio and pixel-count example. Individual converter limits depend on the upload path, route, and mode.
- JPEG normalization uses EXIF orientation when decoding and checks the resulting dimensions. Oversized WebP with EXIF is rejected before resizing when orientation cannot be carried through safely. A newly exported copy with the desired orientation gives the converter a fresh supported image. [MDN orientation reference](https://developer.mozilla.org/en-US/docs/Web/CSS/Reference/Properties/image-orientation#from-image), [MDN image format guide](https://developer.mozilla.org/en-US/docs/Web/Media/Guides/Formats/Image_types#choosing_an_image_format)
- Apple documents HEIF capture, JPEG/PNG export in Preview on supported iPhones, and DNG as the ProRAW file format. Apple Photos can share a JPEG after editing a ProRAW photo. The broader Cricut route has HEIC/HEIF in its input list, but a successful HEIC decode was not established for the deployed runtime. The guide describes recovery by exporting a supported copy and makes no HEIC/DNG conversion claim. [Apple HEIF guide](https://support.apple.com/en-au/116944), [iPhone Preview guide](https://support.apple.com/en-gb/guide/iphone/iph61c20afe1/27/ios/27), [Apple ProRAW guide](https://support.apple.com/en-am/119916)
- `useHybridTraceFetcher.ts` submits eligible fallback jobs with the image while the page is active and avoids fallback for canceled and browser-only centerline runs. The PNG route uses the server retry time when present. `TraceOutputPanel.tsx` gates Cancel and Retry on job state and route callbacks. The PNG retry handler checks source ownership and can require the same source again.

## Validation and release state

- Local `npm run test:docs`, `npm run test:reliability`, `node --check server.js`, and `git diff --check` on the route passed. Reliability tests covered accepted signatures, normalization and memory rejection, JPEG/WebP EXIF, terminal server responses and retry timing, fallback, and cancellation. These checks do not exercise Apple's photo app.
- Eight recovery cases passed on the immutable PR #12 app at `http://127.0.0.1:5280/png-to-svg-converter`, using Chromium and WebKit at 390 × 844. A mislabeled TIFF signature and a compressed 54 MP JPEG recovered with a 3,000 × 2,000 JPEG copy. An oversized EXIF WebP recovered with an upright PNG copy. The tab-close case opened a fresh tab and selected a transparent PNG. All eight SVG downloads contained paths. The PNG cases rasterized to output with clear and opaque pixels. Generated fixtures, screenshots, downloads, and results are under `tmp/phase2/mobile-workaround-review`.
